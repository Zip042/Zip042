# 홈페이지 병합 설계 — 와이어프레임 × 디자인 가이드

## 배경

- `wf/원룸 계약 사기 방지 와이어프레임.dc.html` — "등기지킴이" 서비스의 PC 화면 와이어프레임. 5개 화면 플로우(홈, 업로드/분석중, 분석결과, 계약 체크리스트, 용어사전·사기사례)로 구성된 저충실도 목업. `Gaegu` 손글씨체와 점선 테두리를 사용하는 스케치 스타일.
- `design-guide/src/app/App.tsx` — "등기지킴이 Design System v0.3" 문서. 브랜드 컬러 후보(레드 `#C0404A` / 그린 `#2A8C5F`) 비교, Foundation(색상·타이포·접근성)/Principles/Flexible Patterns/Anti-patterns 4단 체계, Safe(`#059669`)/Caution(`#D97706`)/Danger(`#EF4444`) 시맨틱 컬러 정의를 포함.
- 목표: 두 산출물을 합쳐 실제로 라우팅되는 홈페이지 프로토타입을 만든다. 지금 단계는 "와이어프레임 구조 + 디자인 가이드 스타일"의 병합만 다루며, 실제 등기부 분석 로직·로그인·저장 등 기능 구현은 이후 별도 작업으로 확장한다 (YAGNI — 지금 만들지 않음).

## 1. 컬러 시스템 — 듀얼 액센트 + 독립 시맨틱

디자인 가이드는 레드/그린을 "브랜드 컬러 중 택1" 후보로 제시했지만, 사용자는 두 색을 함께 활용하길 원했다. 아래와 같이 역할을 분리해 충돌 없이 공존시킨다.

- **브랜드 프라이머리 = 레드 `#C0404A`** (hover `#A83540`, light `#FDECED`) — 로고 포인트, GNB 활성 상태, 메인 CTA(예: "등기부등본 분석하기"), 링크, 포커스 링. "지금 확인하라"는 행동 유도 역할.
- **브랜드 세컨더리 = 그린 `#2A8C5F`** (hover `#22754E`, light `#E6F5EE`) — "진행/확정/긍정" 액션 전용. 체크리스트 완료 항목, "다음 단계로" 버튼, 진행률 바, 완료 배지.
- **시맨틱 컬러 (Safe/Caution/Danger)는 브랜드 색과 완전히 분리된 별도 팔레트**로, 오직 등기부 분석 결과 리포트 화면에서만 사용한다.
  - Safe: 텍스트 `#059669` / 배경 `#ECFDF5` / 테두리 `#A7F3D0`
  - Caution: 텍스트 `#D97706` / 배경 `#FFFBEB` / 테두리 `#FDE68A`
  - Danger: 텍스트 `#EF4444` / 배경 `#FEF2F2` / 테두리 `#FECACA`
  - 브랜드 레드·그린보다 채도가 높고 톤이 달라 "브랜드색"과 "판정 결과색"이 시각적으로 구분된다 (design-guide의 방법 A: 채도 차별화 + 방법 C: 위치 차별화를 함께 적용).

## 2. 타이포그래피 & 기본 스타일

와이어프레임의 `Gaegu` 손글씨체는 "초안 표시용" 스케치 서체이므로 실제 서비스에는 사용하지 않고, design-guide가 정의한 서체를 적용한다.

- **Nunito** (700/900) — 로고, h1, 강조 숫자
- **Noto Sans KR** (400/500/700) — 본문, 라벨, 버튼
- **DM Mono** — 등기부 번호, 퍼센트, hex 코드 등 수치·코드 데이터

**Radius 스케일**: sm 8px(배지·태그) / md 12px(버튼·인풋) / lg 16px(카드) / full(pill 뱃지)

**카드/간격**: 흰 배경 + 얇은 border + lg radius, 섹션 간 `py-8`~`py-12` — design-guide 데모 페이지의 리듬을 재사용.

## 3. 아키텍처 & 기술 스택

- **위치**: 새 `app/` 폴더에 독립 Vite + React + TypeScript 프로젝트를 생성한다. `design-guide/`는 스타일 레퍼런스로, `wf/`는 와이어프레임 원본 보관용으로 그대로 둔다.
- **스타일링**: Tailwind CSS v4 + `@tailwindcss/vite`. CSS 변수 기반 `theme.css`에 위 1절 컬러를 새로 정의한다 (design-guide의 기존 `theme.css`는 기본 shadcn 핑크 테마라 재사용하지 않고, 새 토큰으로 교체).
- **컴포넌트**: `design-guide/src/app/components/ui/*` (Radix 기반 shadcn 프리미티브: button, card, badge, checkbox, progress 등)를 `app/src/components/ui/`로 복사해 재사용. 프레임워크 종속성 없는 순수 프리미티브라 안전하게 재사용 가능.
- **라우팅**: `react-router` v7 (선언적 모드). 라우트:
  - `/` 홈(랜딩)
  - `/analyze` 업로드·분석 중
  - `/analyze/result` 분석 결과 리포트
  - `/checklist` 계약 체크리스트
  - `/glossary` 용어사전·사기사례
- **공통 레이아웃**: `Layout.tsx`에 헤더(로고 + GNB 3개: 등기부 분석/계약 체크리스트/용어사전 + 로그인 버튼)를 두고 모든 페이지가 공유한다. 와이어프레임 홈 화면의 GNB는 4개 항목("사기 사례" 별도)이었으나, 하위 화면들의 실제 GNB는 3개로 통일되어 있어 3개로 맞추고 "사기 사례"는 용어사전 페이지 내부 섹션으로 둔다.
- **데이터**: 백엔드 없음. 업로드 진행률(62%), 위험 판정 결과, 체크리스트 상태는 와이어프레임에 그려진 값을 그대로 목업 데이터 + 로컬 React state로 구현한다. 실제 PDF 분석, 로그인, 저장/영속화는 이번 범위에 포함하지 않는다.

## 4. 페이지별 콘텐츠 매핑

| 라우트 | 내용 | 비고 |
|---|---|---|
| `/` | 히어로("30초 만에 위험 확인") + CTA 2개("등기부등본 분석하기" / "체크리스트 먼저 보기") + "이렇게 확인합니다" 3단계 + "요즘 많이 당하는 수법" / "사회초년생 필수 3가지" 2단 카드 | 이미지 자리는 회색 플레이스홀더 박스 유지 (실제 에셋 없음) |
| `/analyze` | 드래그앤드롭 업로드 박스 + 진행률 바(목업 62%) + "무엇을 확인하나요" 사이드 패널 + "서류가 없다면" 대체 경로 | 실제 파일 업로드/분석 로직 없음, UI만 |
| `/analyze/result` | 위험도 원형 배지 + 항목별 판정 카드(위험 3 / 정상 2) + "지금 할 일" / "전문가 상담" 사이드 | Safe/Caution/Danger 시맨틱 색 적용 구간 |
| `/checklist` | 좌측 4단계 스텝 네비("집 보러 가기 전"/"계약 당일"/"잔금·입주"/"입주 후") + 우측 체크리스트 항목(클릭 시 로컬 state로 체크 토글) + 진행률 바 | 저장/PDF 출력은 버튼만 존재, 동작 없음 |
| `/glossary` | 용어 검색바 + 필터 칩 + 용어 아코디언 리스트(근저당권/확정일자/대항력/신탁등기/전세가율) + "실제 사기 사례" / "피해를 당했다면" 사이드 카드 | 사기 사례 섹션 포함 |

## 5. 폴더 구조

```
app/
├─ package.json, vite.config.ts, index.html
├─ src/
│  ├─ main.tsx
│  ├─ styles/ (theme.css - 새 컬러 토큰, fonts.css, tailwind.css)
│  ├─ components/
│  │  ├─ ui/ (design-guide에서 복사한 shadcn 프리미티브)
│  │  └─ Layout.tsx (헤더/GNB 공통 레이아웃)
│  └─ pages/
│     ├─ Home.tsx
│     ├─ Analyze.tsx
│     ├─ AnalyzeResult.tsx
│     ├─ Checklist.tsx
│     └─ Glossary.tsx
```

## 6. 검증

자동 테스트는 추가하지 않는다 (정적 UI 프로토타입 단계). 구현 완료 후 dev 서버를 띄워 5개 라우트를 브라우저로 직접 열어 레이아웃·색상·네비게이션 동작을 확인한다.
