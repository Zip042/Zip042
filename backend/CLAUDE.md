## 절대 깨지 말아야 할 설계 원칙

이 네 가지는 **서비스의 신뢰성 자체**와 직결됩니다. 리팩터링하다 무너뜨리기 쉬우니 주의하세요.

### 1. AI 는 판독만, 판정은 규칙 엔진이

```
문서 ──AI(추출만)──▶ 구조화 데이터 ──규칙 엔진(결정론적)──▶ 위험 판정 · 특약
```

`src/domain/*` 은 전부 순수 함수이고 외부 의존이 **하나도 없습니다**. 이걸 유지해야
같은 문서가 같은 판정을 받고, 판정 근거를 조문·숫자로 설명할 수 있습니다.

- AI 추출 스키마(`src/schemas/extraction.ts`)에 **위험 판단 필드를 추가하지 마세요.**
  모델이 "안전해 보입니다"라고 말하는 순간 이 서비스는 못 쓰게 됩니다.
- 추출 스키마의 모든 필드는 `nullable` 입니다. "모르겠다"를 표현할 방법이 없으면
  모델이 값을 지어냅니다.

### 2. 모르는 값을 0으로 채우지 않는다

이 서비스에서 가장 위험한 실패는 **조용한 실패**입니다. 시세 조회 실패는
`source: "unavailable"`, 다가구 선순위 보증금 미상은 `null` 로 두고, 둘 다
**사용자에게 보이는 finding** 으로 올립니다.

특히 `evaluateValuation` 에 `seniorDepositKrw: 0` 을 넘기면 "선순위 없음"으로
판정됩니다. 모르는 경우는 반드시 `null` 을 넘겨야 합니다
(`analysis.service.ts` 의 `multiHousehold` 분기 참고).

### 3. "위험하다"와 "모른다"는 다른 축이다

초기 구현에서 **"사진이 흐림"만으로 87점 매우 위험**이 나왔습니다. 정보 부족과 실제 위험을
같은 점수에 더한 탓입니다. 지금은:

- `Finding.kind: "risk" | "info_gap"` — `info_gap` 은 **위험 점수에 더해지지 않습니다**
- `info_gap` 중 심각한 것(시세 미확인, 채권최고액 판독 실패, 다가구 선순위 미상,
  등기부 미제출)은 `blockingGaps` → `contractable = false`
- 그때 headline 은 "위험합니다"가 아니라 **"아직 판단할 수 없어요"**
- 같은 카테고리 내 두 번째 이후 항목은 기여도를 체감시킵니다(1, 0.5, 0.25…)

`info_gap` 을 새로 추가할 때는 `kind: "info_gap"` 을 빼먹지 마세요. 빼먹으면
점수가 부풀고 위 문제가 재발합니다.

### 4. 지역 통계는 계약을 단독으로 거부하지 않는다

반경 내 피해 밀도(`REGION_NEARBY_VICTIMS`)는 **최대 danger** 입니다. 등기부가 깨끗하고
서류가 맞는 계약을 동네 통계만으로 "계약 불가"로 만들면 오판이고, 사용자는 판정을
신뢰하지 않게 됩니다.

반면 **동일 건물 · 동일 소유자** 피해는 이 물건·이 임대인에 대한 직접 증거이므로
`critical` 을 유지합니다. 이 구분을 없애지 마세요.

## 밟기 쉬운 함정

| 함정 | 설명 |
|---|---|
| **날짜를 Date 객체로 다루기** | 일정 계산의 핵심은 "전입신고 **다음 날 0시 KST**" 같은 한국 시간대 날짜 경계입니다. `src/lib/date.ts` 는 전부 `YYYY-MM-DD` 문자열 기반이고, 타임존 변환은 고정 오프셋 `+09:00` 만 씁니다. Date 산술로 바꾸면 서버 타임존에 따라 판정이 달라집니다. |
| **금액 단위 혼용** | 내부는 **항상 원(KRW) 정수**. 프론트는 `amountUnit: "krw" \| "man"` 으로 명시하고 스키마 계층에서 정규화합니다. 만원/원을 섞으면 100배 오차가 납니다. |
| **채권최고액 ≠ 대출 잔액** | 등기부의 채권최고액은 담보 한도(보통 실제 대출의 110~120%)입니다. 보수적으로 이 값을 씁니다. AI 프롬프트에도 "채권액이 아니라 채권최고액"이라고 못박아 두었습니다. |
| **RLS 에만 의존하기** | 사용자 소유 목록 조회는 RLS **와 별개로** 코드에서도 `user_id` 를 필터합니다. `service_role` 클라이언트가 실수로 전달되면 RLS 가 우회되어 전체 사용자 데이터가 새기 때문입니다(이중 방어). 새 목록 엔드포인트를 만들 때도 이 패턴을 따르세요. |
| **`adminClient()` 남용** | 기본은 `userClient(token)` 입니다. `adminClient()` 는 사용자가 볼 수 없는 데이터(피해주택 원본 등)를 다룰 때만 쓰고, 그때는 case 소유권을 코드에서 직접 검증해야 합니다. |
| **Hono 미들웨어 범위** | `app.route("/v1", api)` 안에서 `api.use("*", requireAuth)` 를 하면 `/v1/admin/*` 까지 사용자 인증을 요구합니다(실제로 이 버그가 있었고 테스트가 잡았습니다). 지금은 `AUTH_PATHS` 에 경로를 **명시적으로 열거**합니다. Hono 의 `/x/*` 는 `/x` 자체를 포함하지 않으니 두 형태를 모두 등록해야 합니다. |
| **목 모드 쿼리 빌더는 지연 실행** | `MockQuery` 는 `await` 할 때 실행됩니다. `void query` 로 부르면 **아무 일도 일어나지 않습니다**(실제로 시드가 조용히 안 돌던 버그가 있었습니다). 동기 컨텍스트에서는 `store.table()` 에 직접 쓰세요. |
| **목 모드가 운영과 달라지는 것** | 목이 제약을 흉내내지 않으면 "목에서만 통과하는 코드"가 생깁니다. `analysis_jobs` 의 부분 unique 인덱스처럼 **동작 차이를 만드는 제약은 목에도 넣었습니다**(`UNIQUE_CONSTRAINTS`). 새 제약을 추가하면 목도 함께 맞추세요. |
| **npm 스크립트에 `VAR=x cmd` 쓰기** | POSIX 셸 전용 문법이라 **Windows 에서 실행되지 않습니다**(cmd.exe 가 `VAR` 을 명령어로 해석). 팀원 OS 가 섞여 있으니 환경변수는 진입점 파일에서 `process.env.X ??= ...` 로 설정하세요 (`src/server.mock.ts` 참고). |
| **공유 `adminClient()` 에 세션 심기** | supabase-js 는 요청마다 `세션 토큰 ?? supabaseKey` 순으로 인증 헤더를 고릅니다. 캐시된 `adminClient()` 로 `signInWithPassword` 를 부르면 **그 순간부터 service_role 이 아니라 방금 로그인한 사용자**가 되어, 이후 모든 서버 내부 호출이 RLS 에 막힙니다. 비밀번호 로그인은 `passwordAuthClient()`(캐시 안 함)로만 하세요. |
| **`process.env` 직접 읽기** | 모든 설정은 `src/env.ts` 의 `EnvSchema` 를 거칩니다. 직접 읽으면 오타가 검증을 통과해 **조용히 기본값·폴백으로 동작**합니다(주소 검색 키가 실제로 이 문제였습니다). 예외는 플랫폼이 주입하는 `process.env.VERCEL` 뿐입니다. |
| **`.env` 를 라이브러리 코드에서 읽기** | `loadDotEnv()` 는 **진입점에서만** 부릅니다(`server.ts` · `scripts/*`). 라이브러리나 테스트 경로에서 부르면 테스트가 개발자의 로컬 `.env` 에 따라 다르게 동작합니다. 이미 설정된 환경변수를 덮지 않는 것도 규칙입니다 — 플랫폼 주입값이 항상 이깁니다. |

## 프론트엔드와의 대응

프론트엔드는 별도 저장소입니다 — `Zip042/Zip042` 의 `develop` 브랜치 `app/`.
로컬에서는 `../zip042-front/app` 에 받아 두었고, dev 프록시로 이 서버에 붙습니다.

| 프론트 화면 | 백엔드 |
|---|---|
| `/` 홈 | 정적 마케팅. 서버 호출 없음 |
| `/analyze` 등기부 업로드 | `POST /v1/cases/{id}/documents/upload-url` → `POST .../documents` |
| `/analyze/documents` 추가 서류 | 같음 (docType 만 다름) |
| `/analyze/details` 계약 조건 | `PUT /v1/cases/{id}` — leaseType · 보증금 · 월세 · 계약일 · 잔금일 · 전입신고일 |
| `/analyze/result` 판정 | `POST /v1/cases/{id}/analyze` → `GET .../analysis` |
| `/checklist` | `GET /v1/checklist` (공개) + `GET·PUT·DELETE /v1/checklist/progress` |
| `/glossary` | `GET /v1/glossary` · `/glossary/fraud-cases` · `/glossary/relief-steps` (전부 공개) |

**프론트에 전용 화면은 없지만 화면 문구가 요구하는 것들** — 지우면 그 문구를 만들 수 없습니다.

- `schedule.ts` → AnalyzeDetails 의 "잔금일과 전입신고일 사이 4일은 대항력이 없는 상태입니다"
- `special-terms.ts` → AnalyzeResult 의 "특약사항에 '잔금일까지 근저당 말소' 조건을 넣으세요"
- `address.service.ts` → AnalyzeDocuments 의 "서류가 없으면 주소로 조회해 대신할 수 있습니다"

**아직 프론트에 흔적이 없는 것** (기획서에는 있음): 지역 위험 레이어(2②) · 대화형
후속 질문(2④) · 알림 발송함 · 홈 요약. 프론트 설계 문서가 "이후 별도 작업으로 확장
(YAGNI — 지금 만들지 않음)"이라고 명시했으므로 **뺀 것이 아니라 미룬 것**입니다.

### 말소 필터가 왜 별도 파일인가

가이드가 "제일 위험한 지점"이라고 못박은 부분입니다. 이미 갚아 없어진 근저당은
**취소선**으로 그어져 있는데 **취소선은 글자가 아닙니다.** 판독이 놓치면 이미 갚은 3억을
살아 있는 빚으로 계산해 멀쩡한 집이 위험으로 뜹니다.

그래서 두 겹으로 막습니다.

1. AI 의 `isCancelled` (취소선·'말소' 표시)
2. **코드** — 말소는 `"3번근저당권설정등기말소"` 라는 **글자**로도 남습니다. 이걸 파싱해
   대상 순위번호를 지웁니다. AI 가 놓친 것을 코드가 잡으면 `rescuedByCode` 에 남깁니다.

`registry-risk.ts` 는 이제 `r.isCancelled` 를 직접 필터하지 않고 `separateCancelledRights()`
를 씁니다. **되돌리지 마세요.**

### 검산을 422 로 끊지 않는 이유

가이드는 검산 실패 시 422 "판독 불가"를 권합니다. 의도(틀린 판정보다 침묵이 낫다)에는
동의하지만, 이 서버는 그 의도를 `info_gap` → `blockingGaps` → `contractable = false` →
headline "아직 판단할 수 없어요" 로 **이미 구현**하고 있습니다. 422 로 끊으면 읽어낸
나머지 정보까지 버립니다. 결론은 같고, 사용자가 얻는 정보는 더 많습니다.

## 팀이 확정한 API 목록 (집톡 필요 API 요약, 2026-08)

반영한 결정 두 가지입니다.

- **지역 통계는 위험 점수에 넣지 않습니다.** 보유 데이터가 자치구 단위 집계뿐이고 좌표가
  0건이라 반경 계산이 성립하지 않습니다. `REGION_NEARBY_VICTIMS` 는 `severity: caution`
  고정 · `weight: 0` 입니다. 동일 건물 · 동일 소유자 피해는 이 물건·이 임대인에 대한 직접
  증거이므로 `critical` 을 유지합니다(설계 원칙 4).
- **전월세 실거래가 엔드포인트**를 `RENT_ENDPOINTS` 로 정리했습니다. 아직 조회에 쓰지
  않습니다 — 키를 받아 `npm run preflight -- --only molit` 로 응답 형식을 확인한 뒤 붙이세요.

위 목록은 **전부 붙였고 실호출로 확인했습니다** (2026-08-27) — 도로명주소, 건축HUB
건축물대장, 공동주택가격(파일 방식으로 전환), 국세청 사업자 상태조회, 법제처 조문, 카카오 주소.

법제처만 성격이 다릅니다: 키가 아니라 **호출하는 서버의 IP·도메인을 open.law.go.kr 에
등록**해야 열립니다. 등록 안 된 곳에서 부르면 "사용자 정보 검증에 실패하였습니다" 가
옵니다 — 키 문제로 오해하기 쉽습니다. 개발 PC 가 바뀌거나 배포처가 바뀌면 다시 등록하세요.

## 실행 모드

`ZIP042_MODE` = `live` | `mock`. 비우면 `SUPABASE_URL` 유무로 자동 판단합니다.

- **`NODE_ENV=production` + mock 은 부팅이 차단됩니다** (env 검증 단계). 실데이터 없이
  그럴듯한 응답을 내보내는 사고를 막기 위한 장치이니 풀지 마세요.
- 목 모드가 흉내내지 **않는** 것: RLS. 사용자 격리 검증은 반드시 실제 Postgres 에서
  `supabase/tests/verify_rls.sql` 로 하세요.
- `src/mock/` 은 어댑터일 뿐입니다. 도메인 로직은 두 모드에서 **완전히 동일한 코드**가 돕니다.

커밋된 `openapi.json` 과 다르면 실패합니다 — 프론트엔드가 낡은 타입으로 개발하는 것을 막습니다.

외부 연동은 실제로 호출해 봐야 확인됩니다. 두 스크립트가 그 용도입니다.

```bash
npm run preflight                              # 키별 실제 호출 1회 → ✅/❌ 와 다음 조치
npm run extract -- ./등기부.pdf registry        # DB·업로드 없이 판독만 (프롬프트 튜닝용)
```

`preflight` 를 CI 에 넣지 마세요. 실제 외부 호출을 하고 Anthropic 검사는 과금됩니다.

`tests/http/mock-flow.test.ts` 가 **전체 파이프라인을 CI 에서 검증**합니다 —
검사 건 생성 → 서명 업로드 → 문서 등록 → 판독 → 규칙 엔진 → 판정 저장 → 조회.
live 모드에서는 AI·공공 API 때문에 불가능한 테스트이므로, 목 모드의 가장 큰 가치가 여기입니다.

마이그레이션은 **실제 PostgreSQL 16 + PostGIS 3.4 에서 적용·검증**했습니다
(RLS 격리, PostGIS RPC 집계, 부분 unique 인덱스 동작, 고아 작업 정리 함수).
로컬에 `supabase` CLI 가 없으면 Docker 로 `postgis/postgis:16-3.4` 를 띄워
`supabase/tests/verify_rls.sql` 을 돌릴 수 있습니다.
(주의: arm64 맥에서 이 이미지는 amd64 에뮬레이션으로 돌아 간헐적으로 죽습니다.
단계 사이에 `docker start` 로 되살리며 진행하세요.)

## 지금까지 잡은 실제 버그 (재발 방지용)

테스트가 잡은 것들입니다. 비슷한 변경을 할 때 참고하세요.

1. 인증 미들웨어가 `/v1/*` 전체에 걸려 관리자 경로까지 401 → 경로 명시로 수정
2. 목 시드가 `void query` 라서 실행되지 않음 → 저장소 직접 쓰기로 수정
3. "사진이 흐림"이 87점 매우위험 → `info_gap` 축 분리 (원칙 3)
4. 지역 밀도만으로 모든 케이스가 critical → 밀도 상한 danger (원칙 4)
5. 작업 큐 멱등성 경쟁 조건 → 충돌 시 기존 작업 반환 + 목에도 unique 제약
6. 홈 요약이 남의 검사 건 반환 → 명시적 `user_id` 필터 (이중 방어)
7. 알림 배지가 "오늘 0건 / 예정 13건"으로 혼란 → `due` / `pending` 분리
8. `npm run dev:mock` 이 Windows 에서 실행 불가 (`ZIP042_MODE=mock tsx ...` 는 POSIX 전용)
   → `src/server.mock.ts` 진입점으로 대체. CLAUDE.md 가 안내하는 주 명령이었는데 아무도 몰랐습니다
9. `.env` 를 읽는 코드가 **아무 데도 없었음** — `.env.example` 만 있고 로딩이 없어서
   키를 넣어도 서버가 못 봤습니다 → `loadDotEnv()` (`process.loadEnvFile` 기반, 의존성 없음)
10. 주소 검색 키만 `process.env` 직접 읽기 → 오타 시 조용히 목 데이터 폴백. `EnvSchema` 로 이동
11. `scripts/` 가 tsconfig `include` 밖이라 타입 검사·CI 가 스크립트를 검사하지 않았음
12. 로그인 한 번이 **전체 서비스**를 깨뜨림 — `signIn` 이 캐시된 `adminClient()` 로
    `signInWithPassword` 를 불러 공유 클라이언트가 그 사용자로 바뀌었고, 그 뒤 모든
    사용자의 문서 업로드가 RLS 위반으로 실패. 서버 재시작 전까지 낫지 않았습니다.
    증상(업로드 실패)이 원인(로그인)과 달라 보여 진단이 오래 걸렸습니다.
    → `passwordAuthClient()` 분리 + `tests/services/auth-client-isolation.test.ts`
12. **AI 판독이 한 번도 동작한 적이 없었음** — SDK 의 `betaZodOutputFormat` 이 내부에서
    zod 4 API(`z.toJSONSchema`)를 부르는데 이 저장소는 zod 3 이라 즉시 예외. SDK peer 가
    `^3.25.0 || ^4.0.0` 이라 설치는 조용히 성공했고, **키가 없어 실호출을 못 해 본 동안**
    아무도 몰랐다. → 판독 파일 하나만 고치고(zod-to-json-schema + SDK 의 공개
    `transformJSONSchema`), **키 없이 도는 회귀 테스트**를 붙였다
    (`tests/services/extraction-output-format.test.ts`)
13. `kakaoProvider` 가 예외만 던지는 스텁인데 `resolveProvider()` 는 키만 있으면 그걸 골랐음
    → 키를 넣는 순간 주소 검색이 목 폴백도 못 하고 전멸. 실제 구현으로 교체
14. 공공데이터포털 키가 이미 URL 인코딩돼 있는데 `URLSearchParams` 에 넣어 **이중 인코딩** →
    본문 없는 HTTP 403. 실거래가·공휴일·preflight 세 곳에서 같은 함정을 밟고 있었다
15. 성공 코드가 API 마다 다름(`00` · `000` · `0000` · `0`) — `000` 을 성공으로 안 봐서 실패 처리
16. 공동주택가격은 **REST API 가 아니라 파일 다운로드**였다(포털 "API 유형: LINK").
    실제로 부르면 `NO_OPENAPI_SERVICE_ERROR`. 브이월드에서 반기마다 받아 import 하는 방식으로 전환

## 개인정보 처리

- **판독이 끝나면 Storage 원본 파일을 지웁니다** (`purgeCaseFiles`, `analysis.service.ts` 에서 호출).
  화면이 "서류는 분석 후 즉시 삭제 처리됩니다"라고 약속하므로 코드가 그 약속을 지킵니다.
  `documents` 행과 `document_extractions` 는 남습니다 — 어떤 서류가 제출됐는지는 판정의
  입력이고(등기부 미제출은 blockingGap), 판독 결과가 있어야 재조회가 됩니다.
  **대가**: 강제 재판독(`reparse`)이 안 됩니다. 프롬프트 튜닝은 `npm run extract` 로 하세요.
  이 동작을 지우려면 프론트 문구(`data/document-checks.ts` 의 `UPLOAD_NOTICE`)도 함께 고쳐야
  합니다. 안 고치면 화면이 거짓말을 하게 됩니다.

- **피해주택 개별 주소는 클라이언트로 절대 나가지 않습니다.** 집계값과 격자 좌표만 반환합니다.
  `victim_properties` 는 RLS 정책을 만들지 않아(deny-by-default) 클라이언트가 직접 SELECT 할 수 없고,
  `security definer` RPC 만 열어둡니다.
- **소유자 이름은 원문을 저장하지 않습니다.** HMAC(`MATCH_KEY_PEPPER`) 키만 저장·비교합니다.
  이름은 엔트로피가 낮아 단순 해시로는 역추적이 가능하기 때문입니다.
  페퍼가 없으면 동일 소유자 탐지 기능이 **비활성화**됩니다.
- 저장소에 실제 피해주택 주소를 커밋하지 마세요. 개발용 더미는 `(가상)` 접두어로 구분합니다.
